PATENT AUTOMATION — OVERVIEW

AI Agent 기반 특허 출원 자동화

출원인이 고팡(Gopang) 채팅 앱을 통해 자신의 AI 비서에게 특허 출원을 지시하면, AI 비서가 출원인의 Private Data Vault에서 관련 연구 기록과 아이디어를 인출하고, 변리사 Agent·특허청 Agent 등 외부 기관 Agent를 호출하여 전체 출원 과정을 자율적으로 수행합니다. Private Data Vault에 접근할 수 있는 것은 오직 해당 출원인의 AI 비서뿐이며, 외부 Agent에게는 AI 비서가 필요한 정보만 선별 제공합니다.

고팡(Gopang): 사람과 AI Agent 간의 소통 경로

고팡은 출원인과 AI 비서 간, 그리고 필요시 출원인과 외부 기관 Agent 간의 직접 소통을 지원하는 채팅 앱입니다. 출원인은 고팡을 통해 AI 비서에게 업무를 지시하고, AI 비서가 변리사 Agent·특허청 Agent와 소통하며 업무를 진행합니다. 출원인이 직접 외부 Agent와 대화해야 할 경우에도 고팡이 그 소통 경로 역할을 합니다.

기존 방식

전문 변리사 의뢰: 수백만 원

명세서 작성 + 심사: 수십 시간 ~ 수개월

출원 시점 입증: 접수 시각 기준 (분쟁 시 불확실)

Agent Web 방식

고팡에서 AI 비서에 지시 → 자동 처리: 수만 원

명세서 도출 + 심사: 1~2시간

출원 시점 입증: OpenHash 기록 (위변조 불가능)

PROCESS FLOW

특허 출원 자동화 흐름

출원인 → AI 비서: 업무 지시 (고팡)
출원인이 고팡 채팅 앱을 통해 자신의 AI 비서에게 발명의 핵심 아이디어를 설명하고 특허 출원을 지시합니다. 기술 분야, 해결하려는 문제, 핵심 구성요소를 대화 형식으로 전달합니다.
AI 비서: Vault 데이터 인출 및 정리
AI 비서가 출원인의 Private Data Vault에서 관련 연구 기록, 실험 데이터, 개발 이력을 인출합니다. Private Data Vault에 접근할 수 있는 것은 오직 이 AI 비서뿐이며, 외부 Agent에게는 출원에 필요한 정보만 선별하여 전달합니다.
AI 비서 → 변리사 Agent 호출
AI 비서가 변리사 Agent(조력 LLM)를 호출하고, 선별된 아이디어 자료를 전달합니다. 변리사 Agent는 발명의 기술적 특징, 종래 기술과의 차별점, 청구 권리 범위를 파악하고, 선행기술 데이터베이스를 검색하여 선행기술문헌을 수집합니다.
명세서 초안 작성 → 반복 개선
변리사 Agent가 초안을 작성하면, 심사관 Agent(방해 LLM)가 거절 사유를 지적합니다. 이 반복 피드백을 통해 등록 가능성을 극대화한 명세서를 도출합니다. (아래 상세 설명)
도면 및 도면 부호 작성
확정된 명세서에 기반하여, 발명의 구성요소와 동작 흐름을 도시하는 도면을 자동 생성하고, 명세서와 일관된 도면 부호를 부여합니다.
청구항 작성
명세서와 도면을 기반으로, 독립항과 종속항을 체계적으로 구성합니다. 청구항의 범위 설정, 신규성·진보성 확보, 기재 요건 충족을 각각 독립 쟁점으로 검증합니다.
OpenHash 시각 증명 기록
AI 비서가 완성된 출원서 전체의 해시값을 OpenHash 네트워크에 기록합니다. 이 기록은 출원 시각을 특정하며, 위변조가 불가능합니다. (아래 상세 설명)
AI 비서 → 특허청 Agent 제출 및 심사
AI 비서가 특허청 Agent에 출원서를 제출합니다. 특허청 Agent가 신규성·진보성·기재 요건을 자동 심사하고, 1~2시간 내에 등록 또는 거절 여부를 결정하여 AI 비서에 회신합니다.
출원인 최종 승인 (고팡)
AI 비서가 고팡을 통해 출원인에게 심사 결과를 보고합니다. 출원인이 최종 검토하고 승인합니다. 필요시 출원인은 고팡을 통해 특허청 Agent와 직접 소통할 수도 있습니다. 모든 과정은 해시 체인 기반 감사 로그로 기록되어 법적 책임소재가 명확합니다.
ITERATIVE REFINEMENT

조력-방해 Agent 반복 피드백

AI 비서가 호출한 변리사 Agent(A)가 명세서를 작성하면, 심사관 Agent(B)가 거절 사유를 구조화된 지적 사항으로 생성합니다. A가 지적을 반영하여 명세서를 갱신하고, B가 재검토하는 사이클이 수렴할 때까지 반복됩니다. 이 과정에서 Vault 데이터가 추가로 필요하면, 외부 Agent가 AI 비서에게 요청하고 AI 비서가 선별하여 제공합니다.

MODULE A — 변리사 Agent
출원인의 이익을 극대화하는 방향으로 명세서를 작성합니다. 추가 자료가 필요하면 AI 비서에게 요청하고, AI 비서가 Private Data Vault에서 연구 기록, 실험 데이터, 개발 이력을 인출하여 선별 제공합니다.
→ 지적 사항 ← 보정 명세서
MODULE B — 심사관 Agent
특허 등록 거절의 관점에서 명세서를 검토합니다. 신규성 흠결, 진보성 흠결, 기재 불비, 발명의 단일성 위반 등을 구조화된 형식(쟁점 식별자, 심각도, 근거)으로 지적합니다.

수렴 판단 모듈이 코사인 유사도 기반으로 결과물 변동 점수(ΔR)와 신규 지적 점수(ΔC)를 매 라운드 측정합니다. 연속 4라운드(특허 도메인 W=4) 동안 변동이 3% 이하(θR=0.03), 신규 지적이 5% 이하(θC=0.05)이면 수렴으로 판정합니다.

수렴 후, 중재 LLM(MODULE C, 심판관 역할)이 쟁점별 순차 합의를 수행합니다. 청구항 범위, 신규성 판단, 진보성 판단, 명세서 기재 요건을 각각 독립 쟁점으로 분해하여 합의를 도출합니다.

명세서 → 도면 → 청구항 순차 도출

① 명세서 확정 (A-B 반복 수렴 + C 중재 합의)
② 도면 자동 생성 (확정된 명세서의 구성요소·흐름 기반, 도면 부호 자동 매핑)
③ 청구항 작성 (명세서 + 도면에 기반한 독립항·종속항 체계적 구성)
OPENHASH TIMESTAMP PROOF

출원 시각의 위변조 불가능한 증명

특허 출원에서 가장 중요한 요소 중 하나는 '누가 먼저 출원했는가'입니다. OpenHash는 출원서의 해시값과 정확한 타임스탬프를 계층적 DHT 네트워크에 기록하여, 출원 시각을 위변조 불가능하게 특정합니다.

기록 메커니즘

H = SHA-256(출원서 전체)
H′ = SHA-256(H ∥ T) → 계층적 DHT 네트워크에 분산 저장

※ 원본 출원서는 출원인의 Private Data Vault에 암호화 저장
※ DHT에는 이중 해시값(32바이트)만 존재 → 출원 내용 유출 불가

이 기록은 다음을 증명합니다: 해당 출원서가 기록 시점(T)에 존재했다는 사실, 기록 시점 이후 출원서가 변경되지 않았다는 사실, 출원서의 내용이 출원인에 의해 생성되었다는 사실.

글로벌 규모의 적용: 선출원주의의 혁신

OpenHash 네트워크는 대한민국에 국한되지 않습니다. 글로벌 계층(Layer 5)에 분산 저장된 해시값은 전 세계 어디서든 검증 가능합니다.

이는 다음과 같은 효용을 제공합니다:

① 국제 선출원 시각 증명 — PCT(특허협력조약) 출원 시, OpenHash 기록이 출원 시각의 독립적 증거로 기능합니다. 각국 특허청의 접수 시각에 의존하지 않고, 발명의 존재 시각을 기술적으로 증명합니다.

② 선발명 분쟁 해결 — 복수의 출원인이 유사한 발명을 주장할 때, OpenHash 타임스탬프가 객관적 선후 관계를 증명합니다. 합의 메커니즘 없이 O(1)로 검증되므로, 분쟁 해결 비용이 대폭 절감됩니다.

③ 영업비밀의 존재 시점 증명 — 출원 전 단계에서도, 아이디어나 연구 기록의 해시값을 사전 등록하여 '해당 시점에 해당 지식이 존재했음'을 증명할 수 있습니다. 이는 기업의 영업비밀 보호와 기술 탈취 분쟁에서 결정적 증거가 됩니다.
